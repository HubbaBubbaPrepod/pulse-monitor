# Pulse Monitor

Монохромная панель на Next.js, TypeScript и GSAP с центральным Go-бэкендом.

## Разработка

Node.js 22.13+ и Go 1.23+. В двух терминалах:

```powershell
npm ci
npm run dev
```

```powershell
cd backend
D:\Go\bin\go.exe run . -data ../data -static ../out
```

Фронтенд: http://127.0.0.1:3000. В режиме разработки API автоматически подключается к http://127.0.0.1:8080. При недоступном API экран входа предлагает повторить подключение. Данные панели доступны только после входа.

## Одна программа обслуживает панель и API

```powershell
npm run build
cd backend
D:\Go\bin\go.exe build -o ../pulse-monitor.exe .
cd ..
.\pulse-monitor.exe -addr 127.0.0.1:8080 -data data -static out
```

Откройте http://127.0.0.1:8080. Node.js нужен только для сборки. Для Linux соберите Go-программу на целевой платформе либо через GOOS/GOARCH. Бэкенд использует стандартную библиотеку и согласованный golang.org/x/crypto/bcrypt для хранения паролей.

## Первый вход

Откройте /register/ и создайте учётную запись владельца: имя, email и пароль от 12 символов (максимум 72 байта UTF-8). После первого владельца регистрация закрывается. Вход — /login/, выход — кнопка у профиля.

Хэш bcrypt (cost 12) сохраняется в data/account.json. Сессии на 8 часов хранятся в памяти сервера: перезапуск требует нового входа. Cookie HttpOnly/SameSite=Strict; изменения защищены CSRF-токеном, вход ограничен 10 попытками в минуту на IP. Не включайте account.json в публичные файлы; сохраняйте каталог data при обновлении.

## Возможности

- Светлая и тёмная темы, адаптивный интерфейс, GSAP-анимации, скелеты и reduced motion.
- Переключение 2/5/10/30 секунд и реалтайм через SSE: новый снимок каждые 500 мс. Пауза останавливает просмотр, сбор логов продолжается.
- Процессы с иконками, поиском, числовой сортировкой CPU/памяти/PID/GPU/VRAM по заголовкам столбцов и деталями; иконки ОС у серверов.
- Сеть: активные соединения, входящие/исходящие пакеты, адреса и порты, протоколы, флаги, размер, процесс, фильтры, детали и CSV.
- Диски: объём, свободное место, чтение/запись, IOPS, занятость, задержка и температура.
- GPU процессов: нагрузка в процентах и видеопамять в MB, детали и CSV. Отсутствующие показатели — null в API и прочерк в интерфейсе.
- GPU при наличии: нагрузка, VRAM, температура, потребление, вентилятор и график. Демо production-01 включает видеокарту; Windows-узел — без GPU.
- Полный архив логов: фильтры и поиск по всей истории, страницы по 100 записей, переход к первым записям, пауза просмотра и экспорт страницы.
- Серверы сохраняются в data/servers.json. Логи добавляются в data/logs.jsonl, сохраняются после перезапуска и удаления узла. Настройки оформления остаются в браузере.

## Контракт API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | /api/health | Доступность API |
| GET | /api/auth/status | Состояние входа и первого запуска |
| POST | /api/auth/register | Создать первого владельца |
| POST | /api/auth/login | Войти, получить cookie и CSRF-токен |
| POST | /api/auth/logout | Отозвать текущую сессию |
| GET | /api/bootstrap | Реестр, источник и время текущего запуска |
| PUT | /api/servers/{id} | Добавить/обновить сервер |
| DELETE | /api/servers/{id} | Удалить сервер, сохранив архив |
| GET | /api/servers/{id}/snapshot | Метрики, процессы, диски, GPU, соединения и пакеты |
| GET | /api/servers/{id}/stream | SSE события snapshot каждые 500 мс |
| GET | /api/servers/{id}/logs | История, новые записи сначала |

Все маршруты мониторинга требуют сессию, POST/PUT/DELETE — заголовок X-CSRF-Token. Изменения принимают Content-Type: application/json. Поля os, online, cpu, memory, disk при записи сервера принадлежат бэкенду: существующие сведения сохраняются, а новый адрес ожидает агента без ОС и метрик.

Снимок принимает period=15/60/360/1440 минут. История принимает limit (1–200), offset, level (INFO/WARN/ERROR), source, q и before (RFC3339). before фиксирует границу архива для стабильного просмотра старых страниц. Валидация отклоняет неизвестные поля, адреса с паролем и повторные JSON-объекты. Демонстрационные снимки содержат source: demo; реальные — source: agent.

## Реальные узлы

Go-агент реализован в `agent/`: Linux/Windows, gopsutil v4.25.9, CPU/RAM, процессы,
диски, соединения, системные журналы и доступные GPU-метрики. Для пакетов используется
опциональный установленный TShark. Демонстрационные узлы остаются явно подписанными.

Настройки сохранённого сервера → «Создать / заменить токен». Сохраните токен на узле
в файл `agent.token` и выполните предложенную команду. Агент сам отправляет отчёты;
адрес сервера в реестре служит описанием узла. Входящий порт агента не нужен.

```powershell
cd agent
D:\Go\bin\go.exe build -o ../artifacts/pulse-agent.exe .
cd ..
./artifacts/pulse-agent.exe -url http://127.0.0.1:8080 -server SERVER_ID -token-file agent.token
```

Новые API: POST/DELETE `/api/servers/{id}/token`; POST `/api/agent/{id}/report`
с Bearer-токеном; GET `/api/events`; POST `/api/events/{id}/ack` (либо `all`).
Остальные маршруты по-прежнему защищены сессией и CSRF.

Отчёт содержит bootId, sequence, os, hardware, sample, processes, disks, gpus,
connections, packets, logs, capabilities и необязательный logCursor. Повтор с тем
же bootId/sequence не создаёт новые логи. Тело ограничено 2 MB; вход проверяется.
`snapshot.source`: `demo`, `agent`, `waiting`; `samples[].at` — время реальной метрики;
`gpus[].supported` обозначает недоступные аппаратные показатели.

История метрик сохраняется в `data/agents/*.jsonl`, последние отчёты и SHA-256 токенов —
в `data/agents/*.json`, события и отметки — в `data/events.json`. После перезапуска
узел ждёт свежий heartbeat. Нет отчётов 15 секунд — событие потери связи.
Графики читают последние 24 часа с дисковым шагом 10 секунд; SSE показывает текущие данные.

Удалённое размещение поддерживает HTTPS через `-tls-cert`, `-tls-key`, `-public-url`.
Первую учётную запись создайте на loopback, затем включайте удалённый адрес.
