# Изолированные модули WASI

Доступны с Monitor 0.7.0 и Agent 0.6.0. Нативные пакеты схем 1 и 2 сохраняются как режим полного доверия. Поле runtime необязательно: отсутствие или `native` сохраняет нативное выполнение; `wasip1` никогда не переключается на процесс ОС при ошибке.

## Пакет и согласие

Компонент схемы 2 указывает `runtime:"wasip1"` и ровно один артефакт `binaries["wasip1-wasm"]` с SHA-256 и содержимым в base64. Сборка Go-гостя: `GOOS=wasip1 GOARCH=wasm go build`. Нельзя маркировать PE/ELF как WASI. Содержимое и метаданные выпущенной версии неизменяемы.

`requires` — обязательные разрешения; `optionalCapabilities` — дополнительные, которые владелец выдаёт отдельно. Ручной триггер может иметь `requires` из этих двух списков. Хост проверяет их при постановке и авторизации задания; отключённая кнопка не заменяет серверную проверку. Смена runtime, контракта разрешений, полей, триггеров или места выполнения отключает настройки и очищает разрешения до повторного согласия. Совместимые обновления сохраняют настройки. JSON-обновление без Marketplace использует тот же установщик.

Агент объявляет `capabilities.moduleWASI:"1"`, сохраняя `moduleRuntime:"2"`. Старым агентам задания WASI не выдаются. Новое задание содержит `runtime:"wasip1"`; для нативного поле опущено. Скачивание привязано к аутентифицированной операции и точному хешу. Состояние WASI отделено по модулю, компоненту и узлу от прежнего нативного состояния.

Запросы Marketplace по умолчанию возвращают совместимые нативные версии для старых клиентов. Обновлённые клиенты указывают `runtime=all` в каталоге, истории и метаданных точной версии. `executionRuntimes` содержит `native`/`wasip1`; прежнее `runtimes` по-прежнему означает расположение Agent/Monitor. Одобрение относится к одной версии и хешу, включая предварительные релизы.

## Граница и ограничения

Гость получает stdin, ограниченный stdout, часы и криптографический генератор случайных чисел. Каталоги хоста не смонтированы. Переменные окружения, сетевые сокеты, запуск процессов, учётные данные узла и Docker socket гостю не доступны. Из объектов настроек и входа исключаются поля password и служебные ключи `serverId`, `telegramToken`, `telegramChatId`, `socket`. Прежняя секретная классификация полей сохраняется при обновлениях.

Ограничения: артефакт 16 MiB, вход 2 MiB, линейная память гостя 128 MiB, запуск 30 секунд вместе с ожиданием свободного места runtime, stdout/ответ хоста 512 KiB, запрос хоста 64 KiB и максимум 64 вызова посредника. На хосте одновременно допускается не более двух запусков runtime; текущий диспетчер выдаёт ещё меньше. Это не жёсткий предел всего RSS или доли CPU хоста. Go-интерпретатор и посредник остаются доверенной частью приложения.

Закрытое состояние передаётся при `state.read`, возвращённое состояние записывается только при `state.write`. Не копируйте секреты из состояния в публичные результаты. Файлы хранятся с ограничением доступа, но не шифруются на диске. Нативные модули по-прежнему получают права родительского процесса: их разрешения не являются песочницей ОС.

## ABI посредника

Импорт: `pulse_host.request(requestPtr:u32, length:u32, responsePtr:u32, capacity:u32) -> u32`. Вход UTF-8: `{"method":"docker.logs","params":{}}`. Выделите буфер ответа ровно 512 KiB и передайте эту ёмкость. До внешнего действия хост проверяет обе области памяти. Нулевой результат означает отказ ABI; нельзя повторять изменяющую операцию для определения размера ответа.

Ответ: `{ok,status,data,error?}`, где `status` равен `ok`, `error` или `unknown`. Дубли ключей, неизвестные параметры и чужая область отклоняются. Параметры гостя не заменяют идентичность, разрешения, цель или закрытые настройки задания. Результат гостя использует прежний протокол 2: `{protocol:2,status,data,state?,error?}`. Подтверждение хоста приоритетнее заявления гостя: попытку внешнего действия с неизвестным исходом нельзя скрыть ответом `ok`.

## Методы Agent

| Метод                                           | Разрешение                           | Область и лимит                                                                                     |
| ----------------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `docker.snapshot`                               | `docker.read`                        | Фиксированный локальный Docker; один снимок за запуск, до 100 контейнеров                           |
| `docker.logs`                                   | `docker.logs`                        | Точное ручное действие и полный 64-символьный `input.containerId`; последние 200 строк, одно чтение |
| `docker.start`, `docker.restart`, `docker.stop` | `docker.control` + `actions.execute` | Точное изменяющее действие и контейнер задания; максимум одна команда                               |

Параметры снимка пустые. Для контейнера параметры пустые либо повторяют только привязанный `containerId`; остальные поля отклоняются. Произвольные URL Docker, тела HTTP, socket и проксирование недоступны. Посредник использует `/var/run/docker.sock` либо стандартный Windows named pipe Docker. После команды проверяются состояние, настроенный healthcheck и новое StartedAt после перезапуска в пределах 20 секунд. Подтверждение команды Docker не означает готовность сервиса. Docker daemon и агент остаются привилегированными; разрешение управления допускает указанные изменения контейнеров.

## Методы Monitor

| Метод                   | Разрешение               | Область и лимит                                                                                          |
| ----------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------- |
| `telemetry.snapshot`    | `telemetry.read`         | Пустые параметры; заданный владельцем `serverId`; один текущий снимок метрик, оборудования, дисков и GPU |
| `notification.telegram` | `notifications.telegram` | Только `{message:string}`; одна попытка, до 4096 символов / 16 KiB                                       |

В настройках Monitor-компонента можно объявить служебные текстовые `serverId`/`telegramChatId` и password-поле `telegramToken`, без непустых значений по умолчанию. Хост оставляет их закрытыми. Telegram отправляется только в настроенный чат через фиксированный HTTPS `api.telegram.org`, без редиректов и proxy из окружения. Проверяется подтверждение сообщения Telegram; это не доказывает прочтение получателем. Потеря связи или неоднозначный ответ дают `unknown` без автоматического повтора. Новый интервальный запуск — отдельная операция; автор определяет состояние и устранение повторных оповещений.

## Отмена и восстановление

Выключение, перенастройка или обновление отзывает задания и отменяет работу гостя и запросы посредника. Сохранённая уникальная квитанция исключает повторную выдачу той же ручной операции после перезапуска агента. Прерывание после внешнего эффекта может оставить `unknown`; перед новой командой проверьте реальное состояние. Гарантии exactly-once для внешних эффектов нет.

Поддерживаются интервальные и ручные триггеры. Событийная диспетчеризация, постоянная очередь повторной доставки, произвольные нативные API, пользовательские UI-скрипты и долгоживущие задачи не реализованы. Исходник Docker-гостя — `cmd/docker-wasi`, отдельно от прежних нативных socket-клиентов. Используйте новые неизменяемые релизы и явные разрешения для каждого узла.
