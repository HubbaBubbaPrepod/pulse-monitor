# Эксплуатация

## Данные и backup

Все пути относительны `-data`. `account.json` содержит владельца и bcrypt-хэш, `servers.json` — реестр, `preferences.json` — оформление и язык. `agents/*.json` содержит хэши токенов и последние отчёты, `agents/*.jsonl` — историю метрик; `logs.jsonl` — архив журналов, `events.json` — события и отметки. `modules`, `module-config`, `module-data` содержат пакеты, настройки и результаты модулей. Поля типа `password` сохраняются в конфигурации на сервере; скрытый ввод в UI не обеспечивает шифрование или сокрытие от владельца через API.

Остановите панель, скопируйте **весь каталог данных** в защищённое место, затем запустите. Отдельно сохраните TLS-ключи, конфигурацию службы и защищённые файлы токенов на узлах. Для восстановления остановите службу и восстановите каталог целиком с прежними правами. Выход из аккаунта отзывает сессию и не удаляет данные. Сессии хранятся в памяти: после перезапуска нужен новый вход.

Метрики записываются с шагом 10 секунд, графики читают последние 24 часа. Архив JSONL автоматически не очищается; следите за свободным местом. Системные журналы собираются с запуска агента; восстановление после сбоя зависит от сохранности журналов ОС.

## Обновление и удаление

1. Прочитайте changelog обеих программ и сделайте backup.
2. Остановите панель и агенты. Linux: `sudo systemctl stop pulse-monitor` / `pulse-agent`. Windows: `Stop-ScheduledTask -TaskName PulseMonitor` / `Stop-Service PulseAgent`.
3. Замените бинарник и `out` панели из нового архива; агентам замените бинарник. Сохраните данные, токены и состояние агента.
4. Запустите службы и войдите снова. Проверьте отчёты и модули. При откате восстановите соответствующие бинарники, `out` и backup данных; не предполагайте обратную совместимость новых файлов.

Удаление Linux: остановите и отключите unit (`sudo systemctl disable --now pulse-monitor` или `pulse-agent`), удалите соответствующий файл из `/etc/systemd/system`, выполните `sudo systemctl daemon-reload`, затем удалите каталог программы. Windows: остановите и удалите задание (`Unregister-ScheduledTask -TaskName PulseMonitor -Confirm:$false`); для агента `Stop-Service PulseAgent` и `sc.exe delete PulseAgent`. Данные, состояние и токены удаляйте отдельно только если они больше не нужны. Удаление узла из панели сохраняет архив журналов.

## Диагностика

| Симптом                        | Что проверить                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| Панель не запускается удалённо | Владелец создан в используемом `-data`; сертификат, ключ и `-public-url` указаны вместе           |
| TLS error                      | Домен, срок сертификата, полная цепочка, доверие ОС; URL без пути                                 |
| Узел ждёт данных / offline     | `-server`, токен, URL, firewall и исходящий доступ; `pulse-agent -check` проверяет локальный сбор |
| HTTP 401 у агента              | Токен заменён или отозван; обновите файл и перезапустите                                          |
| Нет GPU / журналов / процессов | Права агента, драйвер и `nvidia-smi`; часть показателей ОС недоступна                             |
| Нет пакетов                    | TShark, Npcap на Windows, права захвата, `tshark -D` и `-capture`                                 |
| Модуль error / unsupported     | Пакет для архитектуры, права ресурса, настройки, лимит времени и JSON-протокол                    |

Linux: `sudo journalctl -u pulse-monitor -f` / `pulse-agent`. При ручном запуске ошибки видны в терминале. Не публикуйте токены, TLS-ключи, приватную конфигурацию или необезличенные журналы в Issues.
