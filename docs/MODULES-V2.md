# Нативные модули v 2

Monitor 0.7.0 / Agent 0.6.0 также поддерживают изолированные WASI-компоненты с посредником разрешений. См. [контракт runtime](MODULES-WASI.md). Нативное поведение ниже сохраняется как режим полного доверия.

Статус: ветка разработки, совместимый релиз ещё не опубликован. Сборщики v 1 работают как раньше. Реализованы короткие вызовы на Agent и Monitor, закрытые настройки/состояние, периодический сбор и ручные операции. Доставка событий, выдержанные по времени оповещения, повторы доставки, пользовательские HTML/JS и длительные задания в этот этап не входят.

## Установка и доверие

Загрузите полный JSON со schemaVersion/protocol 2 через «Модули → Установить модуль» или `POST /api/extensions`. В пакете — компоненты с бинарниками Linux amd 64/arm 64 и/или Windows amd 64. Установка сохраняет проверенные файлы, но не включает выполнение. Настройте компонент и явно выдайте разрешения. Компоненты Agent настраиваются отдельно для каждого сервера; компонент Monitor работает на узле самого монитора.

Нативная программа получает права родительского процесса в ОС. Разрешения ограничивают диспетчеризацию и доступ к состоянию через Pulse, но **не являются песочницей ОС**. `network.outbound` не ограничивает адреса запросов программы. Хеш подтверждает целостность, а не доверие автору. Доступ к Docker socket может давать управление хостом даже при выключенных кнопках управления в панели.

Имена компонентов уникальны без учёта регистра. ID пакета не может отличаться только регистром от существующего каталога. Версия неизменяема: ни бинарники, ни метаданные нельзя подменить под тем же номером. Установка/переустановка выключает настройки и сбрасывает разрешения. Для перехода с v 1 сначала удалите активную установку; сохранённые данные автоматически не мигрируют.

## Настройки и API

Маршруты владельца используют прежнюю cookie-сессию; изменения защищены Origin/CSRF.

- `GET /api/extensions` — установленные пакеты v 2 без содержимого бинарников.
- `DELETE /api/extensions/{module}` — выключить, отозвать разрешения и отменить задания; файлы и закрытые данные сохраняются.
- `GET/PUT /api/extensions/{module}/components/{component}/configuration?server={id}` — `{enabled,config,grants,clearSecrets?}`. Для Monitor параметр server не передаётся.
- `GET /api/extensions/{module}/components/{component}/data?server={id}` — последний периодический результат `{version,at,status,data,error?}`. Данные другого сервера и старой конфигурации не выдаются.

Доступны `state.read`, `state.write`, `network.outbound`, `actions.execute`. Все `requires` нужно явно выдать. Ручное действие с `mutating:true` дополнительно требует `actions.execute`. Неподдерживаемые возможности и триггеры событий пока нельзя включить.

GET настроек не возвращает пароли. Пропущенное password-поле сохраняет прежнее значение; `clearSecrets:["field"]` удаляет его явно. Признак секрета сохраняется при обновлении пакета, в том числе при смене password→text. Настройки и состояние лежат в закрытых файлах с правами 0600, где это поддерживается, без шифрования на диске. Назначенный агент получает свою конфигурацию по аутентифицированному соединению. Marketplace не получает телеметрию и учётные данные.

## Контракт процесса

Компонент запускается без shell, получает один JSON в stdin, возвращает один JSON в stdout и завершается:

```json
{
  "protocol": 2,
  "id": "<operation-id>",
  "serverId": "node-id",
  "trigger": "manual",
  "action": "logs",
  "config": {},
  "input": { "containerId": "<full-id>" },
  "state": {},
  "grants": []
}
```

Для Monitor отсутствует serverId. Периодический вызов использует `trigger:"interval"` без action. Ответ:

```json
{
  "protocol": 2,
  "status": "ok",
  "data": { "containerId": "<full-id>", "logs": ["message"] },
  "state": { "cursor": 1 }
}
```

Статус `ok`, `error` или `unknown`; необязательный error — до 256 байт. Data и state являются объектами. stdout — до 512 KiB; процесс — до 30 секунд; задание в очереди истекает через 60 секунд. Состояние читается/записывается только при соответствующих разрешениях. Закодированное состояние ограничено 1 MiB, окончательная квитанция Agent —768 KiB с учётом экранирования JSON. Переполнение даёт явную ограниченную ошибку или неизвестный результат.

State — закрытые данные самого модуля, включая курсоры и возможные реквизиты. Он намеренно не редактируется и не выдаётся публичными API результатов. Из известных password-строк в ключах и значениях публичных Data/Error удаляются прямые совпадения за один проход. Преобразованные/закодированные секреты надёжно распознать нельзя; автор обязан не раскрывать их. stderr отбрасывается.

## Ручные операции и восстановление

`POST /api/extensions/{module}/components/{component}/operations?server={id}` принимает `{action,input}` и отвечает 202 с сохранённой операцией. Статус запрашивается через `GET /api/module-operations/{id}`. В результате связаны ID операции, пакет, компонент, сервер и действие; сохранены времена и несекретная цель. Закрытый Input, Event/State, digest настроек и секреты не выдаются.

Состояния: pending, running, succeeded, failed, unknown, cancelled, expired. Смена настроек/версии/разрешений отменяет ожидающие операции и останавливает дочерний процесс. Права проверяются перед выдачей и при завершении. Нужен Agent, объявляющий `moduleRuntime:"2"`; старый или отключённый агент не получает запрос.

Agent создаёт уникальную сохранённую квитанцию до выполнения: повторная выдача не запускает действие заново. При перезапуске незавершённая операция становится unknown. Потеря ответа не означает, что действие не произошло: перед ручным повтором проверьте фактическое состояние. Автоматического повторения ручных операций нет. На узел выдаётся не более одной активной операции; обычная телеметрия работает независимо.

Периодическое расписание сохраняется, не догоняет пропущенные периоды и держит не более одного незавершённого вызова на компонент/узел. Интервал задаёт минимальную задержку, а не жёсткое время при занятом хосте.

## Представления и действия

Доступны прежние table/cards/chart/logs внутри компонента. Графики используют время реального снимка, разрывы для неизвестных значений, отдельные шкалы и текущую тему. История открытой страницы ограничена 60 измерениями и разделяется по серверу/модулю/настройкам.

Таблица добавляет `rowKey:"id"` и `actions:["logs","restart"]`. Ручной триггер задаёт action, необязательные label, mutating, inputFields, inputKey и resultView. В inputKey передаётся полный ID строки. resultView logs открывает журналы выбранного объекта; ответ обязан вернуть тот же ID. `when:{key:"state",values:["running"]}` управляет доступностью кнопки по наблюдаемому состоянию, но не заменяет серверную авторизацию. Независимые ручные операции поддерживают типизированную форму без таблицы. Изменяющие действия требуют подтверждения; неизвестный исход показан явно.

Docker v 2 использует действия logs/start/restart/stop компонента engine, полный 64-символьный ID и локальный socket/pipe. Ожидание остановки/перезапуска — 5 секунд внутри 20-секундного бюджета. По клику загружаются последние 200 строк выбранного контейнера без изменения общих настроек. Старый logContainer остаётся в совместимом пакете v 1.
