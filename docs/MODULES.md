# Модули

Monitor 0.7.0 / Agent 0.6.0 также поддерживают изолированные WASI-компоненты с посредником разрешений. См. [контракт runtime](MODULES-WASI.md). Нативное поведение ниже сохраняется как режим полного доверия.

## Обновление модулей

При включённом Marketplace страница установленных модулей проверяет обновления привязанного издателя, пока открыта (раз в пять минут), и предлагает кнопку «Обновить». Предварительные версии включаются отдельно. Каждая опубликованная версия по-прежнему проходит модерацию; загруженный пакет сверяется с одобренным SHA-256. Ручной импорт JSON работает при отключённом Marketplace и не обращается к каталогу.

JSON новой версии с тем же ID обновляет модуль без удаления. Совместимые настройки, секреты и права v2 сохраняются. Изменение полей, триггеров, среды исполнения или необходимых возможностей выключает компонент до нового согласия; настройки остаются. При замене v1 на v2 старый манифест архивируется, данные и бинарники сохраняются; компоненты v2 настраиваются отдельно. Нативный код работает с правами учётной записи хоста.

Установка из каталога сохраняет источник и издателя. Для первого обновления вручную установленного модуля нужно явно подтвердить издателя; другой издатель не может заменить существующую привязку. Ручной импорт новой версии снимает её привязку к каталогу.

## Runtime v2

В этой ветке работают нативные компоненты Agent и Monitor с ограниченными по времени периодическими и ручными вызовами. Сборщики v1 поддерживаются. Опубликованные бинарники v0.4.0 не получают v2 автоматически: для интерактивного пакета нужны совместимые новые сборки Monitor и Agent.

[Контракт v2 для авторов](MODULES-V2.md) описывает установку, разрешения, секреты, состояние, операции и действия таблиц. Объявления событий проверяются, но включить их пока нельзя. Оповещения, Telegram, пользовательский JavaScript и длительные задания относятся к следующим этапам.

`GET /api/module-capabilities` сообщает поддерживаемые и устанавливаемые схемы `[1,2]`, среды `agent.process.v2`/`monitor.process.v2`, триггеры `manual`/`interval`. Предварительная проверка владельца `POST /api/module-packages/validate` не меняет файлы и не запускает код; `compatible` учитывает возможности, триггеры и платформу Monitor. Ошибки содержат только пути/коды. Старый `/api/modules` продолжает отклонять v2: используйте `/api/extensions` или импорт в панели.

Лимиты: 1–16 компонентов; до 32 полей и разрешений, 1–16 триггеров на компонент; интервал 5–86400 секунд; 16 MiB на бинарник, 48 MiB всех бинарников, 68 MiB тело запроса, 2 MiB закодированный сохранённый манифест. Имена учитывают файловые системы без различия регистра. Неоднозначный JSON, неизвестные поля, неверные типы, хеши/платформы и непустые пароли по умолчанию отклоняются.

[Схема](modules/module-package-v2.schema.json) описывает формат. Файлы в [examples](modules/examples/) являются шаблонами с пустыми binaries; перед установкой добавьте настоящие сборки и хеши.

## Сборщики v1

Модуль добавляет сборщик данных и представления в панель. В настройках панели загрузите JSON-пакет, затем в настройках нужного узла назначьте модуль, заполните поля и включите его. Агент получает назначение и подходящий бинарник автоматически. При отсутствии сборки для платформы результат — `unsupported`.

## Доверие и права

Сборщик — произвольная нативная программа с правами агента. Песочницы нет. `permissions` описывает ожидаемый доступ для оператора, но не ограничивает ОС. SHA-256 проверяет целостность, а не доверие автору. До загрузки проверьте исходники и происхождение пакета. Запуск агента от root/SYSTEM даёт модулю те же права.

Значения полей `password` хранятся на сервере в приватном каталоге данных и передаются назначенному агенту по HTTPS; владелец имеет доступ к ним через API. Не считайте скрытое поле зашифрованным хранилищем.

## Формат пакета

Один JSON-объект: `schemaVersion: 1`, `protocol: 1`, `id`, `version`, `name`, `author`, `description`, `permissions`, `fields`, `views`, `binaries`. Пример структуры (замените бинарник и digest реальной сборкой):

```json
{
  "schemaVersion": 1,
  "protocol": 1,
  "id": "example",
  "version": "1.0.0",
  "name": "Example",
  "author": "Your name",
  "description": "Example collector",
  "permissions": ["Read local service status"],
  "fields": [{ "key": "endpoint", "label": "Endpoint", "type": "text", "required": true }],
  "views": [
    {
      "kind": "cards",
      "title": "Service",
      "key": "service",
      "columns": [{ "key": "status", "label": "Status" }]
    }
  ],
  "binaries": {
    "linux-amd64": { "sha256": "<64 hexadecimal characters>", "content": "<base64 executable>" }
  }
}
```

`id` и ключи: буквы/цифры, `_`, `-`, первый символ — буква/цифра, длина до 64. Версия: `X.Y.Z` или `X.Y.Z-suffix`, до 48 символов. Бинарники: `linux-amd64`, `linux-arm64`, `windows-amd64`; `content` — base64 байтов исполняемого файла, `sha256` — SHA-256 этих байтов. До 16 MiB на бинарник, 48 MiB суммарно. Архитектура и формат должны соответствовать ключу платформы.

До 32 полей: `text`, `password`, `number`, `boolean`, необязательные `required` и `default`. До 16 представлений; `key` указывает верхнее поле результата:

| kind    | Значение в результате                                                         |
| ------- | ----------------------------------------------------------------------------- |
| `table` | Массив объектов, колонки выбирают ключи строки                                |
| `cards` | Объект, колонки выбирают значения карточек                                    |
| `chart` | Объект числовых значений; последние 60 измерений хранятся в текущем просмотре |
| `logs`  | Массив сообщений                                                              |

Колонка содержит `key`, `label`, необязательный `unit`. Пакет не содержит JavaScript интерфейса: представления строит панель. Меняйте `version` при изменении бинарников; конфликт содержимого существующей версии отклоняется.

## Контракт процесса

Агент запускает сборщик как отдельный процесс, передаёт один JSON в stdin:

```json
{ "protocol": 1, "config": { "endpoint": "local-service" } }
```

Сборщик печатает ровно один JSON-объект в stdout и завершается с кодом 0, например `{"service":{"status":"running"}}`. Диагностические сообщения направляйте в stderr. stdout ограничен 512 KiB; скачивание/установка и запуск одного модуля разделяют таймаут 5 секунд. Агент ждёт 5 секунд между циклами; это не гарантия точного периода при нескольких модулях. Ошибка процесса, таймаут или некорректный JSON дают `error`. stderr не передаётся в панель.

## Docker-модуль

Отдельный [Pulse Module Docker](https://github.com/HubbaBubbaPrepod/pulse-module-docker) собирает версию Docker Engine, контейнеры, CPU/память, счётчики сети и необязательные последние журналы выбранного контейнера. Он выпускается независимо от панели и агента; пакет v1.0.2 использует протокол модулей v1.

Скачайте готовый `docker-module.json` из [Releases модуля](https://github.com/HubbaBubbaPrepod/pulse-module-docker/releases) либо соберите из корня его клона (Go 1.25+, PowerShell 7.4+):

```powershell
./scripts/build.ps1 -Version 1.0.2
```

Результат сборки — `artifacts/releases/docker-module.json`. Загрузите JSON в настройки модулей панели и включите для узла с Docker. На Linux используется Unix socket, на Windows — named pipe. Сборщик выполняет запросы чтения, но доступ к Docker socket обычно даёт привилегированный контроль над хостом; это не граница безопасности. Не открывайте Docker API в сеть ради модуля.

## Проверка релизного пакета

Go-бэкенд может проверить скачанный пакет без изменения рабочего монитора. Из каталога `backend`:

```sh
go test -tags=integration -run='^TestInstallReleasedDockerModule$' -count=1 -v -args -module-package=/absolute/path/docker-module.json -module-sha256=<EXPECTED_SHA256> -module-version=1.0.3
```

Передавайте независимо проверенный SHA-256 и ожидаемую версию релиза. Тест устанавливает настоящий JSON через HTTP-обработчик в `t.TempDir()`, проверяет файлы всех трёх платформ и отказ повторной установки той же версии. Он не запускает бинарники и не подключается к рабочим агентам. Без параметра пакета этот дополнительный тест пропускается.

## Каталог marketplace

Во вкладке **Модули → Маркетплейс** укажите адрес каталога и нажмите «Подключить каталог». По умолчанию подключение отключено. Настройка сохраняется в `data/marketplace.json`. Поддерживается HTTPS-адрес без пути, query и учётных данных; HTTP разрешён только для явно указанного loopback IP, например `http://127.0.0.1:3100`. Имена, разрешающиеся в частные адреса, и перенаправления блокируются. Для удалённого Monitor адрес 127.0.0.1 означает сам сервер Monitor, а не компьютер с браузером.

Каталог запрашивается при открытии вкладки, поиске, переходе по страницам или обновлении. Monitor передаёт только фильтры поиска и запросы выбранного модуля; телеметрия, логи, конфигурация узлов и данные входа не передаются. Агенты к marketplace не обращаются. Отключение запрещает новые обращения и установку по уже загруженному результату; установленные модули продолжают работать.

Выберите модуль и опубликованную версию, проверьте автора, права, платформы, исходники и SHA-256, подтвердите доверие. Monitor повторно запрашивает опубликованную версию, проверяет размер и digest полного JSON, затем использует общий установщик с проверкой заголовков ELF/PE и бинарных хешей. После установки назначьте модуль нужным серверам отдельно. Одобрение в каталоге не является гарантией безопасности нативного кода.

В протоколе v1 идентификаторы модулей глобальны. Установка из каталога не заменяет существующий ID, даже у другого издателя. Обновления доступны через существующий ручной импорт JSON; вкладка «Установленные» и импорт работают без marketplace. Поиск, фильтр платформ и загрузка следующих страниц поддерживаются. Для подключения каталога отдельный аккаунт marketplace не требуется.

API владельца Monitor: `GET/PUT /api/marketplace`, `GET /api/marketplace/catalog?query=&platform=&cursor=`, `GET /api/marketplace/versions?owner=&id=`, `POST /api/marketplace/install` с `{owner,id,version,sha256}`. Изменения защищены существующими cookie-сессией и CSRF. При выключенном источнике обращения к каталогу и установка возвращают 409.

Для сквозной проверки с работающим локальным каталогом добавьте к команде теста релизного пакета `-module-marketplace http://127.0.0.1:3100`. Тест создаёт отдельный временный каталог Monitor, получает опубликованную версию через API каталога и устанавливает её через `/api/marketplace/install`; рабочий Monitor и назначения агентам не меняются.
