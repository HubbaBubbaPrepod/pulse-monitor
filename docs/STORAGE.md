# Хранилище Monitor

Monitor хранит отчёты агентов, точки графиков, собранные логи, события и сроки
хранения логов в `data/pulse.db` (SQLite). Kafka и отдельный сервер базы не нужны.
Учётная запись, остальные настройки и закрытые данные модулей пока сохраняют
существующий файловый формат. Установочные JSON-пакеты модулей не меняются.

## Обновление существующей установки

Остановите старый Monitor до обновления. Новый Monitor сохраняет копии старых
`agents/*.json`, `agents/*.jsonl`, `logs.jsonl`, `events.json`, `servers.json` и
`account.json` в `data/legacy-sqlite-backup`, затем импортирует данные. Исходные
файлы остаются на месте. Нужен свободный диск под исходники, резервную копию и базу.
Первый запуск может занять время; приём HTTP начинается после успешного импорта.

Импорт больших архивов идёт транзакциями по 500 записей с сохранением позиции.
Прерывание позволяет продолжить с последней зафиксированной порции. Повреждённая
запись останавливает запуск с именем файла и позицией, а не пропускается. Изменение
исходника во время незавершённого импорта также останавливает запуск: сначала
нужно согласовать исходник и резервную копию. Не удаляйте копии для обхода ошибки.

После активации базы старые архивы больше не пополняются и не перечитываются при
обычном приёме отчётов. Откат к старому бинарнику с исходными JSON-файлами вернёт
только состояние на момент миграции: новые записи SQLite он не увидит. Сначала
сохраните базу, затем планируйте перенос новых данных; не выдавайте такой откат
за восстановление всей актуальной истории.

## Срок хранения логов

Настройки сервера содержат «Хранение логов в Monitor»: 1, 7, 14, 30, 90 дней,
свой срок от 1 до 3650 дней или «Не удалять автоматически». Новые серверы получают
30 дней. Для серверов из старой установки очистка изначально выключена — обычное
обновление не удаляет прежнюю историю. Включение или сокращение срока требует
подтверждения в форме.

Возраст считается по времени приёма записи Monitor в UTC. Время из системного
журнала остаётся для отображения, но часы удалённого сервера не управляют
удалением. При импорте старые записи получают время импорта: срок хранения
начинается заново, чтобы миграция не удалила архив неожиданно.

Раз в минуту фоновой обработчик удаляет до 1000 подходящих записей для каждого
сервера. При большом накопленном объёме очистка занимает несколько проходов.
Она не удаляет логи на самом наблюдаемом сервере, метрики, события или журнал
действий модулей. Резервные копии также не очищаются этим правилом.

SQLite переиспользует освобождённые страницы. Размер `.db` не обязан немедленно
уменьшиться после удаления строк; блокирующий VACUUM в обработчике запросов не
выполняется. Проверяйте место на диске и храните резервную копию вне рабочего диска.

## Резервная копия и восстановление

```sh
pulse-monitor -data /opt/pulse-monitor/data -backup /backup/pulse-2026-10-17.db
```

На Windows укажите свои пути к `pulse-monitor.exe`, каталогу данных и новому файлу.
Команда создаёт согласованный SQLite-снимок, включая зафиксированные записи WAL,
не перезаписывает существующий файл и завершает работу. Она не запускает обработчик
модулей и не меняет статусы их операций. Для автоматизации используйте уникальные
имена и проверяйте успешный код завершения.

Для восстановления остановите Monitor и сохраните весь прежний каталог данных.
Разместите снимок как `pulse.db` в новом каталоге данных вместе с нужными копиями
учётной записи, определений серверов и файлов модулей. Не смешивайте снимок со
старыми `pulse.db-wal`/`pulse.db-shm`. Запустите ту же совместимую версию и проверьте
узлы, историю и настройки до переключения пользователей. SQLite-снимок сам по себе
не является резервной копией учётной записи или нативных файлов модулей.

Нельзя копировать только открытый `pulse.db`, игнорируя WAL. База использует WAL и
`synchronous=FULL`; подтверждение агенту отправляется после транзакции. Это не
защищает от поломки диска, потери всего сервера или неисправного оборудования.

## Разработка

Для исходников Monitor требуется Go 1.26 или новее; релизный скрипт использует
Go 1.27.2. Драйвер modernc.org/sqlite 1.60.1 включает SQLite 3.53.4 с исправлением
WAL-reset. Сборки пользователей содержат всё необходимое; устанавливать Go или
SQLite на наблюдаемые серверы не нужно.
