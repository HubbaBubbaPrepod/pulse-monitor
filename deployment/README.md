# Установка Pulse

Панель и агент — отдельные бинарники. Node.js и Go нужны только при сборке.
Linux: amd64/arm64. Windows: amd64. Сборка из корня проекта:

```powershell
./scripts/build.ps1
```

Результат: `artifacts/releases/out` и каталоги бинарников для каждой платформы.
Перенесите `pulse-monitor` и `out` на сервер панели; `pulse-agent` — на наблюдаемые узлы.
Существующий каталог `data` сохраните. Не кладите его внутрь `out`.

## Первый запуск панели

Создайте владельца на loopback до открытия удалённого доступа:

```text
pulse-monitor -addr 127.0.0.1:8080 -data data -static out
```

Откройте `http://127.0.0.1:8080/register/`. На удалённом Linux можно временно
пробросить loopback через SSH: `ssh -L 8080:127.0.0.1:8080 user@server`.
Остановите этот экземпляр перед запуском службы. При существующем `data/account.json`
повторная регистрация не нужна.

## Удалённый доступ по HTTPS

Подготовьте DNS и действительный TLS-сертификат для домена. Запуск:

```text
pulse-monitor -addr 0.0.0.0:8443 -data data -static out -tls-cert fullchain.pem -tls-key privkey.pem -public-url https://monitor.example.com:8443
```

Откройте порт 8443 в своём firewall. `public-url` задаёт допустимый Host и Origin.
Удостоверьтесь, что процесс читает закрытый ключ; доступ к нему и `data` должен иметь
только оператор службы. Проверка сертификата агентом включена; собственного режима
отключения TLS-проверки нет. Для внутреннего CA добавьте его в доверенные сертификаты ОС.
Сессии требуют нового входа после перезапуска панели; учётная запись остаётся.

Для Linux отредактируйте пути/домен в `pulse-monitor.service`, создайте пользователя
`pulse` и каталоги `/opt/pulse`, `/etc/pulse`, `/var/lib/pulse`. Дайте пользователю службы
право записи только в каталог данных. Скопируйте unit в `/etc/systemd/system/`, затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pulse-monitor
sudo journalctl -u pulse-monitor -f
```

На Windows панель можно запускать той же командой в PowerShell. Для автозапуска
добавьте её в Планировщик заданий: «при запуске компьютера», без интерактивного окна,
с рабочим каталогом установки и абсолютными путями к `data`, `out` и сертификатам.

## Подключение узла

1. В панели добавьте сервер. Адрес узла — описание его местоположения; агент не
   слушает входящий порт, а сам отправляет отчёты в панель.
2. Откройте настройки сохранённого сервера и нажмите «Создать / заменить токен».
   Новый токен отзывает старый. Сохраните его в `agent.token` на узле, без кавычек.
3. Ограничьте доступ к файлу токена и каталогу состояния. Linux: `chmod 600 agent.token`;
   Windows: оставьте права только оператору службы, SYSTEM и администраторам через ACL.
4. Запустите команду из панели:

```text
pulse-agent -url https://monitor.example.com:8443 -server SERVER_ID -token-file agent.token -state agent-state
```

Каждому узлу — свой токен и каталог состояния. Не запускайте два агента с одним токеном.
ОС определяется автоматически. Без отчётов более 15 секунд узел станет недоступным.
Обычные показатели собираются с интервалом от 500 мс; процессы и диски — от двух секунд,
GPU и системные журналы — от пяти. Длительность системного опроса может увеличить интервал.
Диагностика без подключения: `pulse-agent -check`.

Linux: измените `SERVER_ID` и домен в `pulse-agent.service`, создайте каталоги
`/etc/pulse-agent` и `/var/lib/pulse-agent`, перенесите токен, установите unit и выполните
`systemctl enable --now pulse-agent`. Пример запускается от root, чтобы видеть системные
процессы, соединения и journal. При запуске от обычного пользователя доступ ограничен его правами.

Windows: из административного PowerShell:

```powershell
./install-agent.ps1 -PanelURL https://monitor.example.com:8443 -ServerID SERVER_ID -TokenFile C:\Pulse\agent.token -AgentExe C:\Pulse\pulse-agent.exe
```

Устанавливается служба `PulseAgent` с автозапуском. Остановка: `Stop-Service PulseAgent`.
Для удаления: `Stop-Service PulseAgent`, затем `sc.exe delete PulseAgent`.

## GPU и пакеты

NVIDIA: `nvidia-smi` из драйвера даёт нагрузку, VRAM, температуру и доступные показатели.
Нагрузка процессов: GPU Engine на Windows, `nvidia-smi pmon` на Linux при его поддержке.
Windows также обнаруживает GPU через CIM; для единственной карты GPU Engine даёт общую
нагрузку. Недоступные аппаратные показатели обозначены прочерками. На Linux без
поддерживаемого NVIDIA-интерфейса GPU-телеметрия пока недоступна.

Соединения, PID, адреса/порты и суммарные скорости работают без захвата пакетов.
Скорость отдельного соединения не вычисляется и отображается прочерком.
Для метаданных пакетов нужен установленный TShark и права захвата; на Windows —
работающий драйвер Npcap. Панель не устанавливает драйверы автоматически.
Список интерфейсов: `tshark -D`. Запуск агента с захватом: добавьте `-capture 1`
или имя интерфейса. Выборка ограничена 256 пакетами на отчёт, содержимое пакетов
не сохраняется. Привязка пакета к PID пока не выполняется — процессы видны в соединениях.

## Хранение, обновление и backup

- `data/account.json`: владелец и bcrypt-хэш.
- `data/servers.json`: реестр и настройки.
- `data/agents/*.json`: хэши токенов и последние отчёты; исходные токены не сохраняются.
- `data/agents/*.jsonl`: история метрик с шагом 10 секунд; графики читают последние 24 часа.
- `data/logs.jsonl`: постоянный архив принятых системных и демонстрационных логов.
- `data/events.json`: события и отметки просмотра.
- `agent-state/pending.json`: неотправленный отчёт; `log-cursor` — позиция системного журнала.

Журналы берутся с запуска агента, а не за всю жизнь ОС. Дочитывание после сбоя зависит
от сохранности системного журнала на самом узле. Для общесистемных журналов нужны права.
Демонстрационные узлы подписаны «Демо»; их данные синтетические.

Перед резервным копированием остановите панель, скопируйте весь `data` в защищённое
место, затем запустите панель. Linux: `tar -czf pulse-backup.tar.gz data`;
Windows: `Compress-Archive -Path data -DestinationPath pulse-backup.zip`.
Для восстановления остановите панель и восстановите каталог целиком.

Обновление: остановите службы, замените бинарники и `out`, сохранив `data`, токены
и состояние агентов, запустите службы. При смене токена обновите файл и перезапустите агент.
Архивы автоматически не удаляются. Контролируйте свободное место: JSONL читается
последовательно; крупному развёртыванию потребуется отдельный этап индексированного хранения.
